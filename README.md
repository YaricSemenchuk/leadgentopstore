# App Store Leads → promobile Ads

Пайплайн лидогенерации: тянет топ-чарты App Store по странам и категориям, отсекает
крупных издателей, квалифицирует оставшихся через LLM под мотивированный трафик
promobile, собирает публичные контакты разработчика и отдаёт таблицу лидов с почтой.
Рассчитан на Railway.

## Как работает

```
iTunes RSS: топ-100 по странам × категориям (free, grossing)
        │
        ▼
  iTunes Lookup (издатель, отзывы, сайт, bundleId)
        │
        ▼
  отбор без LLM: ≤100k отзывов у приложения + сигнал (новое, гео, игра/утилита, мало отзывов)
        │  очередь по приоритету, недавно оценённые пропускаются
        ▼
  размер издателя (Lookup по artistId): портфель ≤1M отзывов
        │
        ▼
  Claude Sonnet 5.5: флаги да/нет + сила лида → код считает уровень — до 300 за проход
        │  целевой / под вопросом / мимо
        ▼
  контакты для целевых и «под вопросом»: App Store → Google Play → поддержка / политика / сайт
        │
        ▼
  Postgres ──► /  (дашборд) · /api/leads (JSON) · /api/leads.csv (для рассылки)
```

Почему категории: в общем топе крупных стран одни гиганты (Playrix, TikTok, Meta),
которым мотивированный трафик не продашь. Топ-100 категорий уходит в средний сегмент.

### Уровни лида

| Уровень | Кто | Балл |
|---|---|---|
| **целевой** | независимая небольшая/средняя студия игр или утилит, потребительский стартап — доход зависит от установок | 60–100 |
| **под вопросом** | крупноватый издатель или лицензионный IP; крошечный проект (≤20 отзывов, 1–2 страны); только китайский стор; платная игра; чувствительная категория (форекс, азарт, «взрослые», IPTV); локальная ниша | 30–59 |
| **мимо** | корпорации и их дочки, некоммерческие проекты, приложения к устройствам, франшизы крупных студий, издатели из `EXCLUDE_PUBLISHERS` | 0–29 |

Модель не выбирает уровень сама — с многоступенчатой рубрикой она ошибалась (писала
«некоммерческий проект» и ставила «целевой»). Она отвечает на вопросы да/нет (`flags`) и
оценивает силу лида 0–100 по сигналам; уровень и балл внутри диапазона считает
`src/pipeline/tier.ts`. Объективные признаки (Китай, портфель >250k отзывов, платная игра,
крошечный проект) проверяются по данным и только понижают «целевой» до «под вопросом».

Чего модель не знает (например, что 5minlab — дочка Krafton), закрывается списком
`EXCLUDE_PUBLISHERS`.

### Источники

- `itunes.apple.com/{cc}/rss/top…applications[/genre=…]` — чарты (основной источник;
  при сотнях запросов подряд отвечает 403 — это лимит, запросы повторяются с паузой);
- `rss.marketingtools.apple.com` — запасной для общих top-free/top-paid;
- `itunes.apple.com/lookup` — метаданные и портфель издателя (~20 запросов/мин с IP);
- страница App Store — сайт, поддержка и политика разработчика (из встроенного JSON);
- карточка Google Play по bundleId — почта, которую разработчик указал сам;
- страницы поддержки, политики и сайта — почта, если в Google Play её нет.

### Как выбирается почта

1. Почта из Google Play — всегда первая.
2. Со сторонних страниц берутся только адреса на домене разработчика или ролевые
   (support@, contact@, hello@ …). Юрфирмы, GDPR-представители и регуляторы из
   политик отсекаются; noreply — тоже.
3. Ролевые адреса ранжируются: partners/marketing/hello → contact/info → support →
   privacy/legal.
4. Бесплатный ящик (gmail и т.п.) помечается «личный»: это скорее всего частное лицо.

Сайты за защитой от ботов (Cloudflare и т.п.) отвечают 403 и пропускаются — их не обходим.

### LinkedIn

Сам LinkedIn не парсится: он за логином и антиботом, правила это запрещают, а профили людей —
персональные данные. Вместо этого:

- **прямая ссылка** — если разработчик сам поставил LinkedIn на свой сайт (шапка/подвал);
  берётся только со страниц на домене сайта разработчика, иначе попадает LinkedIn платформы,
  где лежит политика или поддержка (Zendesk, Termly). На мобильных разработчиков это ~5%;
- **ссылки поиска для каждого лида**: компания, люди (founder / CEO / marketing / growth) и
  Google по `site:linkedin.com/company`. Юридический хвост названия («Pte. Ltd.», «Anonim
  Sirketi», «Sp. z o.o.») отрезается; если разработчик — частное лицо, ищется человек по имени.
  Открываются под твоим логином в LinkedIn.

Кнопка **«Дособрать контакты и LinkedIn»** на странице «Что парсить» перепроверяет контакты
без модели — у лидов, собранных до появления LinkedIn, это происходит автоматически
(`contacts_version`).

## Что парсить

Страница **«Что парсить»** (`/settings`) задаёт выборку без передеплоя: страны по регионам,
категории (общий топ, игры, приложения), чарты (бесплатные, по выручке, платные), глубину
(топ-25/50/100), сколько приложений оценивать моделью за прогон, пороги размера и список
исключённых издателей. Внизу — живой расчёт: сколько чартов, примерное время первого сбора
и стоимость оценки. Настройки хранятся в таблице `settings`; без них берутся значения из `.env`.

Кнопка **«Сохранить и запустить сбор»** запускает прогон в фоне (не больше одного за раз);
текущий этап виден в шапке и на странице, история — в таблице `runs`. Если все оценки
модели упали (ключ, лимит расходов, недоступный API), прогон помечается ошибкой с причиной.
`POST /ingest` с токеном запускает тот же прогон для cron.

## Локальный запуск

```bash
npm install
cp .env.example .env     # впиши ANTHROPIC_API_KEY и DATABASE_URL
npm run db:init
npm run ingest -- --dry-run        # сбор + отбор без LLM и без записи в БД
npm run ingest                     # полный проход: сбор, LLM, контакты
npm run ingest -- --contacts-only  # только дособрать контакты
npm run ingest -- --rescore        # переоценить сохранённые лиды без уровня (без запросов к Apple)
npm run ingest -- --rescore-all    # переоценить все — после правки промпта или рубрики
npm run dev                        # дашборд на http://localhost:3000
npm test                           # тесты выбора почты на фикстурах
```

## Деплой на Railway

```bash
railway init
railway add --database postgres     # создаст DATABASE_URL
railway variables set ANTHROPIC_API_KEY=sk-ant-... LLM_PROVIDER=anthropic
railway variables set DASHBOARD_PASSWORD=... INGEST_TOKEN=...
railway up
```

`DASHBOARD_PASSWORD` обязателен: в таблице контакты. Регулярное обновление —
Railway cron с `curl -X POST -H "Authorization: Bearer $INGEST_TOKEN" …/ingest`
(отвечает 202 сразу, проход идёт в фоне) или отдельный cron-сервис `npm run ingest`.

## Конфиг (.env)

| Переменная | Назначение |
|---|---|
| `LLM_PROVIDER` | `anthropic` (Claude) или `groq` (Qwen3-Coder) |
| `ANTHROPIC_MODEL` / `ANTHROPIC_EFFORT` | модель и effort (`claude-sonnet-5-5`, `low`); ~$0.006 за лид |
| `ANTHROPIC_API_KEY` / `GROQ_API_KEY` | ключ выбранного провайдера |
| `COUNTRIES` | коды сторфронтов через запятую; пусто = выборка топ-стран |
| `GENRES` | id категорий через запятую, `all` — общий чарт; пусто = набор из `config.ts` |
| `CHARTS` | `top-free,top-grossing,top-paid` |
| `CHART_LIMIT` | позиций из каждого чарта (≤100) |
| `CONCURRENCY` | параллельных запросов к RSS Apple (3; больше — ловит 403) |
| `EXCLUDE_PUBLISHERS` | подстроки названий издателей, которых не брать (крупные группы под разными юрлицами, напр. Century Games); пусто = список из `config.ts` |
| `MAX_APP_RATINGS` | потолок отзывов у приложения (100 000) |
| `MAX_PUBLISHER_RATINGS` | потолок отзывов на портфель издателя (1 000 000) |
| `MAX_LLM_PER_RUN` | потолок запросов к модели за проход (300 ≈ $1.8 на Sonnet 5.5) |
| `REQUALIFY_DAYS` | сколько дней не переоценивать лид (7) |
| `CONTACTS_CONCURRENCY` / `CONTACTS_RECHECK_DAYS` | параллельность сбора контактов / через сколько дней перепроверять (3 / 30) |
| `DASHBOARD_PASSWORD` | пароль на дашборд и CSV (Basic auth, логин любой) |
| `INGEST_TOKEN` | токен для `POST /ingest` |

## Персональные данные

Почта разработчика — публичный контакт, который он сам указал для своего приложения,
но у инди-разработчиков это часто личный ящик частного лица. Для холодных писем
в ЕС и Великобританию это персональные данные (GDPR): пиши по делу, указывай, откуда
взят адрес, и давай отписку. Отписавшихся не возвращай в рассылку.
